# Docs

Product and engineering documentation that lives alongside the code.

- [vision.md](vision.md): the product vision, and the source of truth for what we're building.
- [spec.md](spec.md): the detailed Phase 1 specification, with numbered, testable requirements.
- [spec-phase2.md](spec-phase2.md): the Phase 2 specification (calendar, appointments, documents and records), with `FR2-`, `NFR2-` and `R2-` requirements.
- [spec-phase3.md](spec-phase3.md): the draft Phase 3 specification (tasks and chores), with `FR3-`, `NFR3-` and `R3-` requirements. Planning only until after the Phase 1 beta.
- [architecture.md](architecture.md): how the app is built, covering the data model, security, sync, AI import, entitlements and operations.
- [backlog.md](backlog.md): the ordered Phase 1 (MVP) backlog.
- [backlog-phase2.md](backlog-phase2.md): the ordered Phase 2 backlog (calendar and documents).
- [backlog-phase3.md](backlog-phase3.md): the draft Phase 3 backlog (tasks and chores).
- [design-system.md](design-system.md): tokens, components and accessibility rules for the chosen direction.
- [design-directions.md](design-directions.md): three visual and UX directions, with a recommendation.
- [decisions-needed.md](decisions-needed.md): decisions and accounts needed from the product owner.
- [privacy/data-inventory.md](privacy/data-inventory.md): every table and processor, with purpose and retention, and the draft App Store and Google Play privacy answers (L-01.1).
- [security/](security/): the Phase 2 threat model and internal security review (L-05), with findings and their issues.

Change `vision.md` only with the product owner's approval. Keep `architecture.md` current in the same PR as any change that affects it.
